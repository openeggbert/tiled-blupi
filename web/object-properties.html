Object Properties

Every game object in a Speedy Blupi level is stored as a 48-byte struct in the BLP file. tiled-blupi exposes these fields as editable properties on each Tiled object. This page documents every property, its BLP struct offset, data type, and meaning.

✓ Verified from sblv.js
All struct offsets and field names are taken from the read and write functions in sblv.js. Offsets are relative to the start of each object's 48-byte struct at 0x9FA4 + slot * 0x30.

Object Struct Overview

The object array starts at BLP file offset 0x9FA4. There are 200 slots, each exactly 48 bytes (0x30). An object slot is considered empty if the 4-byte type field at offset +0x00 is 0. The extension skips empty slots when building the Tiled object layer. 

// Absolute address of field F in object slot N (0-indexed):
address = 0x9FA4 + N * 0x30 + F

type

AttributeValue
Struct offset+0x00
Size4 bytes
BLP typeint32 little-endian
Tiled property typeObjectTypes enum (int)
Value = 0Empty slot — not a real object

The most important field. Determines what kind of game object this is (enemy, item, player start, etc.). The BLP file stores a BLP game type ID (a raw integer like 1, 2, 3…). The extension maps this to an ObjectTypes enum index (0–44) using itemTypesArray.indexOf(typeId) on read.

In Tiled, you set the type property to the desired ObjectTypes enum name (e.g., "Robot (enemy)", "Bomb", "Player 1 Start"). On write, the extension converts the enum index back to the BLP type ID using itemTypesArray[enumIndex].

See Object Types for the full list of all 45 types with BLP IDs and descriptions.

x and y Position

Attributex fieldy field
Struct offset+0x0C+0x10
Size4 bytes4 bytes
BLP typeint32 LEint32 LE
Valid range0–99 (tile columns)0–99 (tile rows)

Object positions in the BLP are stored as tile coordinates (0-indexed tile column and row). The Tiled editor displays objects at pixel positions. The conversion is: 

tiled_pixel_x = blp_tile_x * 64
tiled_pixel_y = blp_tile_y * 64

// On write (reverse):
blp_tile_x = Math.floor(tiled_pixel_x / 64)
blp_tile_y = Math.floor(tiled_pixel_y / 64)

Always use View → Snapping → Snap to Grid in Tiled to keep objects aligned to tile boundaries.

endpoint

Attributeendpoint_xendpoint_y
Struct offset+0x14+0x18
Size4 bytes4 bytes
BLP typeint32 LEint32 LE
Tiled property typepoint (x, y pair)

For moving objects (lifts, conveyors, platforms), the endpoint defines the destination tile that the object moves toward. The object oscillates between its spawn position (A) and the endpoint (B).

In Tiled, the endpoint is exposed as a point type property, which lets you enter an (x, y) coordinate pair in tile units. The endpoint is stored as tile coordinates in BLP (same conversion as position: multiply by 64 for pixel display).

Motion timing example

A lift that moves from tile (5,10) to tile (5,3) in 60 ticks, pauses 20 ticks at the top, returns in 60 ticks, and pauses 10 ticks at the bottom:

  • Object position: x=5, y=10 (bottom = position A)
  • endpoint: x=5, y=3 (top = position B)
  • a_to_b_time: 60
  • b_to_a_time: 60
  • a_wait: 10
  • b_wait: 20

Unknown Fields (Preserved Verbatim)

Several object fields are read from the BLP file and written back unchanged. Their purpose is currently unknown. They are exposed as Tiled properties so their values are visible and not lost on round-trip.

Property nameStruct offsetSizeTypeStatus
field_A+0x0A2 Buint16 LEUnknown — preserved verbatim
field_24+0x244 Bint32 LEUnknown — preserved verbatim
field_26+0x262 Buint16 LEUnknown — preserved verbatim
field_28+0x282 Buint16 LEUnknown — preserved verbatim
field_2E+0x2E2 Buint16 LEUnknown — preserved verbatim

Additionally, the 6 bytes at +0x04 to +0x09 are not exposed as properties but are zeroed on write.

tileset_id and tile_id (Read-Only)

FieldOffsetSizePurpose
tileset_id+0x2A2 B uint16Game renderer's tileset index for drawing the object sprite. Not used by the extension for logic. Preserved verbatim.
tile_id+0x2C2 B uint16Game renderer's tile index within the tileset. Preserved verbatim.

These fields control how the game draws the object's sprite. The extension does not modify them; it preserves whatever values were in the original file.

Project Overview

A detailed look at what tiled-blupi is, what problem it solves, what it contains, the maturity of the current implementation, and how to read the evidence tags used throughout this documentation.

Background: The Speedy Blupi Games

Speedy Blupi (1997) and Speedy Blupi II (1999) are side-scrolling platform games developed by Daniel Roux and published by Epsitec SA. Blupi is a recurring character in the Epsitec game universe. Both games store their level data in a proprietary binary format with the file extension .blp. Each level file is exactly 50,468 bytes and encodes a fixed 100×100 tile grid with up to 200 interactive objects and a set of header fields controlling music, scrolling, background image, and level name.

The games were released for Windows and are available from blupi.org. Their level files are stored in a DATA/ subfolder of the game installation. Standard levels are named WORLD###.BLP; custom user levels are named u###-###.blp.

What tiled-blupi Is

✓ Verified from README.md
"Tiled extensions for Blupi map formats."

tiled-blupi is an open-source repository that provides the glue between the Tiled map editor and the Speedy Blupi binary level format. It is hosted at github.com/openeggbert/tiled-blupi.

The repository contains two independent sets of files, one for each game:

  • Speedy Blupi/tiled/ — files for Speedy Blupi (SB1). The JavaScript extension registers format ID sblv ("Speedy Blupi level").
  • Speedy Blupi II/tiled/ — files for Speedy Blupi II (SB2). The JavaScript extension registers format ID sb2lv ("Speedy Blupi 2 level").

Each set is self-contained: it has its own sblv.js extension, its own .tiled-project configuration file, and its own tileset directory with PNG tile images. There is no shared library between SB1 and SB2 — the two extensions are structurally identical but maintain separate copies.

What Each Component Does

ComponentFileRoleWithout it
JavaScript extension extensions/sblv.js Implements the read() and write() functions for the BLP format. Called by Tiled every time a .blp file is opened or saved. Tiled cannot open or save .blp files.
Tiled project file *.tiled-project Tells Tiled to load the extension from extensions/, shows the tilesets/ and ../DATA folders in the project panel, and registers the Object class and ObjectTypes enum for the Properties panel. The extension is not loaded; custom property types are unavailable; DATA folder is not accessible from the panel.
TSX tileset files tilesets/*.tsx Define each tileset's tiles, their image sources, optional tile classes, hflip flags, and tile offsets. Tiled reads these to display tiles in the canvas and tile palette. Tiled shows blank or error tiles. Object type markers and player starts are invisible.
PNG tile images tilesets/<name>/N.png 64×64 pixel images, one per tile, extracted from the game. These are the actual graphics displayed in Tiled. Tiled shows pink/missing-image boxes instead of game graphics.

What tiled-blupi Enables

  • Open any standard WORLD###.BLP or custom u###-###.blp level file in Tiled as a fully editable map.
  • See the foreground tile layer displayed with the correct game graphics (object tileset).
  • See the decoration layer displayed with explo tileset tiles (64 pixels lower than their grid position, matching in-game rendering).
  • See all game objects (enemies, items, hazards, moving platforms) as visual markers in an object layer.
  • See player spawn positions for all 4 players as special markers.
  • See the background image loaded from the game's IMAGE16/ or IMAGE08/ folder in a locked background layer.
  • Edit all the above — tiles, objects, properties — using Tiled's standard tools.
  • Save back to the original .blp binary format for immediate use in the game.

What tiled-blupi Does NOT Do

  • Does not include the game executable, game audio, or any copyrighted game assets beyond the tile images.
  • Does not provide a standalone editor — it is a plugin for Tiled.
  • Does not support all .blp files in the DATA folder. Only WORLD###.BLP and u###-###.blp are level files. Attempting to open other .blp files will produce errors.
  • Does not fully decode the BLP format. The 804 bytes between the name field and the foreground layer, as well as the trailing ~512 bytes, are of unknown structure and are zeroed on save.
  • Does not validate data on save (tile IDs, object counts, property ranges).
  • Does not support any game other than Speedy Blupi and Speedy Blupi II.
  • Does not include tools to extract tile images from the game — the PNG files in the repository are already extracted.

BLP Format — Brief Technical Summary

Every .blp level file is exactly 50,468 bytes. All multi-byte integers are little-endian. The file layout is:

OffsetSizeContent
0x000064 BHeader (7 decoded fields + 24 B name + padding)
0x0040804 BUnknown header data (written as zeros)
0x036420,000 BForeground tile layer (100×100 × uint16, column-major)
0x518420,000 BDecoration tile layer (same format)
0x9FA49,600 BObject array (200 × 48 bytes)
0xC324~512 BUnknown trailing data

See BLP Format for the complete specification with all field offsets.

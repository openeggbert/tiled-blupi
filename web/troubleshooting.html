Troubleshooting

Solutions to common problems when installing and using tiled-blupi. If your problem is not listed here, check the FAQ or the Known Limitations page.

The Custom Format Doesn't Appear When Opening a .blp File

Symptom
When you try to open a .blp file in Tiled, the format selector does not show "Speedy Blupi level" or "Speedy Blupi 2 level".

Causes and fixes:

  1. The project file was not opened.
    You must open the .tiled-project file first. Merely having the extension installed is not enough — Tiled only loads extensions when a project file that references them is open. Go to File → Open and open speedyblupi.tiled-project or speedyblupi2.tiled-project.
  2. The extension failed to load.
    Open the Tiled scripting console (View → Views and Toolbars → Console). If there is a JavaScript syntax error in sblv.js, it will be shown there. Verify that the sblv.js file is present at tiled/extensions/sblv.js.
  3. The extensionsPath is wrong.
    Verify that the project file's "extensionsPath" value is "extensions" and that the extensions/ folder is at the same level as the project file.
  4. The tiled folder is in the wrong place.
    The tiled/ folder must be directly inside the game installation directory, not inside any other subfolder. Check that the structure matches the installation instructions.

The Level Opens But Shows No Tiles (Blank Canvas)

Symptom
The level file opens without error, but the canvas shows a blank grid with no tiles visible.

Causes and fixes:

  1. Wrong format selected.
    If you chose "Speedy Blupi 2 level" for an SB1 file (or vice versa), the tile values may be misinterpreted. Close and reopen the file, selecting the correct format.
  2. The tile PNG images are missing.
    Tiled may show a blank canvas if the PNG images for the object tileset cannot be found. Verify that the tilesets/object/ directory exists and contains numbered PNG files.
  3. The Foreground layer is hidden.
    In the Layers panel, check that the Foreground layer's visibility (eye icon) is turned on.
  4. The file is not a level file.
    Only WORLD###.BLP and u###-###.blp files are level files. Other .blp files in the DATA folder may parse without error but produce empty content.

Objects Are Not Visible

Symptom
The level opens but no objects appear in the Objects layer, or some appear as blank/missing.

Causes and fixes:

  1. The Objects layer is hidden.
    Toggle the eye icon next to the Objects layer in the Layers panel.
  2. The Object Types PNG directory is missing.
    Verify that tilesets/Object Types/ exists and contains the correct number of PNG files (34 for SB1, 44 for SB2).
  3. The Player Start PNG directory is missing.
    Player start objects use tilesets/Player Start/ (4 PNG files). Verify it exists.
  4. The level genuinely has no objects.
    Some levels may have all 200 object slots empty. This is valid — the Objects layer would be empty.

The Background Image is Not Showing

The background image is loaded from the game's IMAGE16/ or IMAGE08/ folder. If the tiled/ folder is not placed inside the game directory (one level above the IMAGE16/ folder), the extension cannot find the background images.

If the background image is missing, the Background layer will be blank. This does not affect editing or saving — the background is display-only.

Save Produces a Corrupted Level

Always keep backups
Before editing any level file, copy the original to a safe location. Save corruption cannot be undone.

Common causes:

  • Unknown header region zeroed.
    The extension writes zeros to the 804-byte unknown header region (0x40–0x363). Some levels may store important data there. If a level crashes the game after editing, compare the saved file to the original using a hex editor.
  • More than 200 objects.
    If you placed more than 200 objects, the extension silently truncates. Objects beyond the 200th are discarded without warning. Keep object count at or below 200.
  • Wrong format used for save.
    If you opened an SB1 file with the SB2 format (or vice versa) and saved, the output will have incorrect minor_version and potentially incorrect object type IDs.

Changing background Property Doesn't Update the Background Image

This is expected behavior. The background image is loaded once when the level is opened. Changing the background map property updates the value in the BLP file on save, but Tiled does not refresh the displayed image. Close and reopen the level to see the new background.

The Game Crashes After Loading an Edited Level

Possible causes:

  • The unknown header region (0x40–0x363) was zeroed and contained critical game data. This is a known limitation.
  • Invalid tile IDs — tile index values beyond the tileset size. The extension does not validate these.
  • Invalid object type IDs — using SB2-only object types in an SB1 level.
  • The major_version was accidentally changed to a non-1 value.

In all cases, restore the backup and repeat the edit more carefully.

Tiled Reports a JavaScript Error When Loading the Project

Check the scripting console for the exact error message. Common issues:

  • File not found: The sblv.js path does not match extensionsPath.
  • Syntax error: The sblv.js file is corrupted or modified incorrectly. Re-download from the repository.
  • API incompatibility: The Tiled version is too old to support scripted map formats. Upgrade to Tiled 1.3 or later.

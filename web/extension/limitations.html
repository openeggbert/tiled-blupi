Extension Limitations

Known limitations and gaps in the current sblv.js implementation, from a code perspective. See also Known Limitations for the user-facing view.

Unknown Header Region (0x40–0x363) Zeroed on Write

804 bytes between the name field and the foreground layer are of unknown structure. The extension writes zeros here. If the original file had data in this region, it is lost on save. This is the most significant known data loss issue.

Unknown Trailing Data Zeroed on Write

Approximately 512 bytes from offset 0xC324 to the end of the file are zeroed. Their purpose is unknown.

Object Fields +0x04–+0x09 Zeroed

6 bytes at the start of each object struct are zeroed on write. Their purpose is unknown.

tileset_id and tile_id Not Reconstructed

The object struct fields at +0x2A (tileset_id) and +0x2C (tile_id) determine which game sprite renders the object. The extension preserves them verbatim on round-trip but does not set them for newly added objects. New objects may have zero or garbage values for these fields, causing incorrect or missing sprite rendering in-game.

No Object Count Warning

If more than 200 objects are placed in Tiled, the extension silently writes only the first 200. Objects beyond the limit are dropped without any error or warning message.

No Input Validation

The write function does not validate:

  • Tile ID range (writing a tile ID beyond the tileset's tile count)
  • Object position range (values outside 0–99)
  • Negative or zero values for fields that should be positive
  • major_version = 1 check on write (it just writes whatever the property says)

Background Layer Not Written

The Background image layer is display-only. Changing the background map property updates the BLP header value (which determines which image the game loads), but the image displayed in Tiled is not updated — you must close and reopen the level.

No Create-from-Scratch Support

Tiled's write() function is not the same as a "New Map" function. If you create a new blank TileMap in Tiled and save it as a .blp file, the result may not be a valid level because several required fields might not be initialized. Always start from an existing level file.

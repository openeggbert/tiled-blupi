Object Properties Reference

Each game object is stored in the BLP file as a 48-byte (0x30-byte) struct. The sblv.js extension maps certain fields from this struct to Tiled custom properties on the object. This page is the complete reference for all object properties.

Object Struct Layout

Every object slot in the BLP file occupies 0x30 bytes. The 200 slots start at absolute file offset 0x9FA4 and occupy bytes 0x9FA4–0xC223 (inclusive).

Slot n starts at: 0x9FA4 + n * 0x30

Struct OffsetProperty Name in TiledBLP TypeMeaningNotes
+0x00type field (internal)uint16 LEBLP game type IDDetermines object behavior. Derived from the tile's class/type in the tileset, not directly editable as a property.
+0x02—uint8[8]Unknown fields +0x02–+0x09Written as zero by sblv.js on save. Original values from the game are lost.
+0x0AfieldAuint16 LEUnknown fieldRead and stored; meaning not documented.
+0x0Cxuint16 LEHorizontal grid position (0–99)Set by Tiled from the object's pixel position ÷ tile_size. Math.floor applied.
+0x10yuint16 LEVertical grid position (0–99)Set by Tiled from the object's pixel position ÷ tile_size.
+0x14endpoint_xuint16 LEMotion endpoint X coordinate0 = no horizontal motion endpoint set.
+0x18endpoint_yuint16 LEMotion endpoint Y coordinate0 = no vertical motion endpoint set.
+0x1Ca_to_b_timeuint16 LETicks to travel from A to B0 = object does not move toward B.
+0x1Eb_to_a_timeuint16 LETicks to travel from B to A0 = object does not move back toward A.
+0x20a_waituint16 LETicks to wait at position A0 = no wait at A.
+0x22b_waituint16 LETicks to wait at position B0 = no wait at B.

+0x2Efield_2Euint16 LEUnknownRead and stored; written back as-is.

Position Coordinate System

The BLP file uses a grid coordinate system where the top-left corner is (0, 0) and the bottom-right is (99, 99). Coordinates are stored as uint16, so they can theoretically hold values 0–65535, but only 0–99 are valid for a 100×100 grid.

Tiled stores object positions as pixel coordinates. sblv.js converts between them:

// Reading: pixel → grid
pixel_x = grid_x * tile_width
pixel_y = grid_y * tile_height

// Writing: grid ← pixel
grid_x = Math.floor(pixel_x / tile_width)
grid_y = Math.floor(pixel_y / tile_height)

Motion Timing

The four timing fields (a_to_b_time, b_to_a_time, a_wait, b_wait) are measured in game ticks. The exact tick rate of Speedy Blupi is not documented in this repository. Based on common game conventions, 60 ticks ≈ 1 second is a reasonable estimate, but this should be verified by experimentation.

Worked example: An object that takes 3 seconds to travel from A to B, then waits 2 seconds at B, then takes 3 seconds back, with no wait at A:
  • a_to_b_time = 180 (3 s × 60 Hz)
  • b_to_a_time = 180
  • a_wait = 0
  • b_wait = 120 (2 s × 60 Hz)

Map Properties Reference

When sblv.js reads a .blp file, it extracts certain values from the file header and stores them as Tiled custom map properties. When writing, it reads these same properties back and encodes them into the binary header.

This page is the authoritative reference for every map property the extension uses.

Evidence key: ✓ sblv.js = confirmed by reading the extension source code. ~ Inferred = based on offset analysis but not directly labeled in the code. ? Unknown = the field exists in the binary but its meaning is not confirmed.

Complete Map Properties Table

Property NameTiled TypeBLP OffsetBLP TypeEvidenceSafe to Edit?Notes
major_versionint0x0000uint16 LE✓ sblv.jsNoSB1=1, SB2=2. Changing causes the extension to reject the file on next read (version check fails).
minor_versionint0x0002uint16 LE✓ sblv.jsNoSB1 default=2, SB2 default=3. Do not change.
backgroundint~0x0010uint16 LE~ InferredWith careIndex of the background image. Valid range is not documented; use values from existing levels.
musicintvariesuint16 LE~ InferredWith careIndex of the background music track. Use values from existing levels.
ambianceintvariesuint16 LE~ InferredWith careAmbient sound layer index. Use values from existing levels.
Unknown header region: The BLP header occupies bytes 0x0000–0x0363 (868 bytes). Only a small number of fields in this region are decoded by sblv.js. The remaining bytes are read but not mapped to properties; when writing, sblv.js zeros this unknown region. This means any data the original game stored in undecoded header fields is lost when you round-trip the file through tiled-blupi. Do not edit levels and re-save them if you need to preserve the original header exactly.

How to Access Map Properties in Tiled

  1. Deselect all tiles and objects (press Escape).
  2. The Properties panel shows the map's custom properties.
  3. Or use Map → Map Properties… from the menu.

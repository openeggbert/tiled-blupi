Layers Reference

A Speedy Blupi level in Tiled is represented by exactly four layers. This page is the complete reference for each layer: its purpose, storage in the BLP binary, the tileset it uses, and the formula for accessing individual cells.

Background Layer

The background layer is added by sblv.js when reading a file, as a visual aid only. It is not stored in the BLP binary file. When writing, sblv.js does not write any background layer data — only the background map property (an index) is written to the header, and the game engine renders the background from its own asset library based on that index.

Do not paint tiles on the Background layer; changes will be lost on save.

Foreground Layer

The main terrain layer. Stores the tile index for each cell of the 100×100 grid.

  • Tileset: element (one PNG image per tile)
  • Storage: Column-major order. Cell (x, y) is at byte offset: 0x0364 + (y + 100*x) * 2
  • Empty cell value: 0xFFFF (65535) — sblv.js converts Tiled's "no tile" to this value on write, and converts 0xFFFF to "no tile" on read
  • Non-empty cell value: Zero-based tile index into the element tileset
  • Edit tool: Stamp Brush, Eraser, Fill, Terrain Brush — any Tiled tile-painting tool
Column-major explained: Most people think of grids as row-major (row 0 first, then row 1, etc.). The BLP format uses column-major order: column 0 (all 100 rows) is stored first, then column 1, etc. The formula y + 100*x converts (x, y) to the linear index in this column-major array.

Example: Cell at x=3, y=5 → index = 5 + 100×3 = 305 → byte offset = 0x0364 + 305×2 = 0x0364 + 610 = 0x05C6.

Decoration Layer

Visual-only decorations painted on top of the terrain. Same grid size and storage structure as the Foreground layer.

  • Tileset: explo
  • Storage: Column-major order. Cell (x, y) is at byte offset: 0x5184 + (y + 100*x) * 2
  • Empty cell value: 0xFFFF
  • Special: The explo tileset has tileoffset y=64 — tiles are rendered 64 pixels below their grid position. This is defined in the TSX file, not a BLP-level setting.

Objects Layer

Contains all game entities. Stored as an array of 200 fixed-size structs.

  • Tilesets: object-types (for regular objects) and player-start (for player starts, type IDs 200–203)
  • Storage: Array of 200 × 0x30-byte structs at BLP offset 0x9FA4
  • Slot n starts at: 0x9FA4 + n * 0x30
  • Maximum objects: 200 (including player starts)
  • Unused slots: Zeroed in the BLP file; sblv.js writes zeros for any slot not occupied by a Tiled object

Layer Order in Tiled

sblv.js creates the layers in this order (top to bottom in the Layers panel):

  1. Objects (topmost — selected by default when adding objects)
  2. Decoration
  3. Foreground
  4. Background (bottommost)

See also: Layers in the main docs and Layer Conversion for the detailed read/write logic.

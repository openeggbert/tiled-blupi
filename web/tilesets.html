Tilesets Overview

tiled-blupi includes nine tilesets for each supported game. This page explains the purpose of each tileset, which layer it is used for, how tiles are numbered, and the differences between the Speedy Blupi and Speedy Blupi II versions.

What is a Tileset?

A tileset is a collection of tile images referenced by a Tiled editor layer. Each tile has a unique 0-based integer ID. tiled-blupi uses individual PNG files per tile (not a single sprite sheet), so each tileset references a directory of images named 0.png, 1.png, and so on.

object — Foreground Tileset

The most important tileset. Contains all foreground gameplay tiles: ground tiles, platforms, walls, ladders, doors, and decorative foreground elements. 246 tiles in SB1, 441 tiles in SB2 (additional SB2 tiles provide new environment graphics). Tiles are indexed 0–245 (SB1) or 0–440 (SB2).

Used exclusively by the Foreground tile layer. The BLP tile value in the file is the direct tile index into this tileset. 0xFFFF = empty cell.

explo — Decoration Tileset

Contains large background decoration elements such as plants, rocks, structural scenery, and environmental backgrounds that appear behind gameplay tiles. 54 tiles in SB1, 100 tiles in SB2.

The tileset has a critical tile offset of y=64 pixels: 

<tileoffset x="0" y="64"/>

This shifts every tile 64 pixels downward from its logical grid position. A decoration placed at grid row N will visually appear at the position of row N+1. This matches in-game rendering. Plan decoration placements with this offset in mind.

Player Start Tileset

4 tiles representing the 4 player spawn positions. All 4 tiles are identical in SB1 and SB2. The tiles use class Blupi in the TSX definition. Tiles 2 and 3 have hflip enabled, mirroring them horizontally.

Player start objects use BLP type IDs 200–203 (for players 1–4). The extension maps these to tiles 0–3 in this tileset.

Object Types Tileset

34 tiles (SB1) or 44 tiles (SB2) used as visual markers for game objects in the Objects layer. Tile index N corresponds to ObjectTypes enum index N, which maps to BLP type ID itemTypesArray[N].

Tile 0 has the class Endpoint and is used to mark the endpoint position for moving objects (where they travel to). In the editor, you place an Endpoint object at the destination and the extension reads its position as the endpoint property of the linked object.

Display-Only Tilesets

The element and blupi000–blupi003 tilesets are included in the project and visible in Tiled but are not used by sblv.js for reading or writing BLP level data.

  • element — appears to contain additional sprite or tile graphics not directly used in level editing.
  • blupi000–blupi003 — animation frame sheets for the four player characters. Useful as a reference when designing levels.

TSX File Format

Each tileset is described by an XML file with the extension .tsx (Tiled Set XML). Each tile is defined as an individual image source (relative path to a PNG file): 

<?xml version="1.0" encoding="UTF-8"?>
<tileset version="1.10" name="object" tilewidth="64" tileheight="64"
         tilecount="246" columns="0">
 <grid orientation="orthogonal" width="1" height="1"/>
 <tile id="0">
  <image source="object/0.png" width="64" height="64"/>
 </tile>
 <tile id="1">
  <image source="object/1.png" width="64" height="64"/>
 </tile>
 …
</tileset>

Image paths are relative to the TSX file's own location.

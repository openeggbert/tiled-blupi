Tutorial 8: Create a Moving Object

Some game objects in Speedy Blupi can move back and forth between two positions on a schedule — for example, a platform that swings left and right, or an enemy that patrols between two points. This tutorial shows you how to configure these motion properties.

Which objects can move? Any object in the object-types tileset can have motion properties set. Whether the game actually animates the motion depends on the object type and what behavior the game engine assigns to it. Not all object types support motion — only those for which the game has patrol/platform logic.

Concept: Motion Properties

A moving object oscillates between two points:

  • Point A — the object's primary position (set by the object's x, y coordinates on the canvas).
  • Point B — the endpoint position, set by the endpoint_x and endpoint_y properties.

The timing is controlled by four properties measured in game ticks (the game's internal time unit, not seconds):

PropertyBLP Offset in Object StructMeaning
a_to_b_time+0x1C (uint16)Number of ticks to travel from A to B
b_to_a_time+0x1E (uint16)Number of ticks to travel from B back to A
a_wait+0x20 (uint16)Ticks to pause at A before starting the trip to B
b_wait+0x22 (uint16)Ticks to pause at B before starting the trip back to A

Step 1: Place the Object at Its Starting Position (Point A)

  1. In the Tilesets panel, select the object-types tileset.
  2. Click the tile for the object type you want (e.g., a platform or enemy).
  3. Use the Insert Tile Object tool to place the object on the canvas at position A — the starting point.

Step 2: Select the Object and Open Its Properties

  1. Press S for the Select tool.
  2. Click the object you just placed. Its properties appear in the Properties panel.

Step 3: Set the Endpoint (Point B)

  1. In the Properties panel, find the endpoint_x property.
  2. Double-click the value and enter the x grid coordinate of Point B (0–99).
  3. Find endpoint_y and enter the y grid coordinate of Point B.
Example: If the object is at x=10, y=20 and you want it to move to x=20, y=20 (horizontal motion), set endpoint_x=20, endpoint_y=20.

Step 4: Set the Travel Times

  1. Find a_to_b_time in properties and set it to the number of ticks for A→B travel. A value of 60 is approximately 1 second if the game runs at 60 Hz.
  2. Find b_to_a_time and set it. You can use the same value as a_to_b_time for symmetric motion, or a different value for asymmetric.

Step 5: Set Wait Times (Optional)

  1. Find a_wait and enter the number of ticks to pause at Point A. Use 0 for no pause.
  2. Find b_wait and enter the pause at Point B. Use 0 for no pause.
Worked example: A platform that moves from x=5 to x=15, takes 2 seconds each way, and waits 1 second at each end:
• endpoint_x = 15, endpoint_y = (same as start y)
• a_to_b_time = 120, b_to_a_time = 120 (120 ticks ≈ 2 s at 60 Hz)
• a_wait = 60, b_wait = 60 (60 ticks ≈ 1 s at 60 Hz)

Step 6: Verify the Endpoint Is Visible

Tiled does not draw a line or marker from the object to its endpoint. To visually confirm the endpoint position, you can temporarily place a tile at that grid cell on the canvas, note the coordinates, then remove it. Alternatively, use Tiled's coordinate display in the status bar — hover your mouse over the endpoint cell and read the x, y shown.

Step 7: Test In-Game

Save the level (Tutorial 9) and load it in Speedy Blupi. Observe whether the object moves correctly. Adjust a_to_b_time / b_to_a_time to tune the speed.

Remember: If the object type does not support motion in the game engine, the motion properties will be stored in the file but will have no effect. The game decides what to do with each object type.
Done! You have configured a moving object. Next: Tutorial 9: Save a Level.

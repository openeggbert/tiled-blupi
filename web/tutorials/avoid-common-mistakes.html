Tutorial 10: Avoid Common Mistakes

This tutorial is a reference list of the most common mistakes made when editing Speedy Blupi levels with tiled-blupi. Each mistake is explained, along with how to detect it and how to recover.

Mistake 1: Opening a .blp File Without Loading the Project First

Symptom: Tiled opens the file as raw data, shows an error, or treats it as an unknown format. The map may appear as a 1×1 map or refuse to open.

Cause: The sblv.js extension (which teaches Tiled how to read .blp files) is only loaded when the associated .tiled-project file is open. Without it, Tiled does not know what a .blp file is.

Fix: Always open the .tiled-project file first using File → Open File or Project. Then open the .blp file. See Tutorial 2.

Mistake 2: Painting Tiles on the Wrong Layer

Symptom: Tiles appear visually in the right place, but do not behave correctly in-game (walls you can walk through, or decoration tiles that block movement).

Cause: Painting on the Decoration layer when you meant to paint on the Foreground layer (or vice versa). Both layers are visible simultaneously so the mistake is not visually obvious in Tiled.

Fix: Always check the active layer name in the Layers panel and the status bar before painting. Foreground tiles go on the Foreground layer; decorative tiles go on Decoration. Use Ctrl+Z to undo misplaced tiles.

Mistake 3: Resizing the Map

Symptom: After saving, the file size is not 50,468 bytes. The game may crash or refuse to load the level.

Cause: Using Tiled's Map → Resize Map feature. The BLP format requires exactly 100 columns × 100 rows. Any other size produces a malformed file.

Fix: Never resize a BLP-backed map. If you accidentally resized, undo immediately (Ctrl+Z) before saving. If you already saved a resized map, restore from your backup copy.

Mistake 4: Exceeding 200 Objects

Symptom: Some objects appear in Tiled but are missing in-game after saving. No error is shown.

Cause: The BLP object array holds exactly 200 entries. If you place more than 200 objects in Tiled's object layer, sblv.js writes only the first 200 and silently discards the rest.

Fix: Count your objects before saving. Select all objects on the Objects layer (Ctrl+A while the layer is active) and read the count from the status bar. Keep it at 200 or fewer — including player start objects.

Mistake 5: Using the Wrong Project File for the Game Version

Symptom: Object types that exist in SB2 but not SB1 are missing from the tileset, or the tileset shows different tiles than expected.

Cause: Opening an SB2 level while the SB1 project is loaded (or vice versa). The two project files contain different sblv.js files and different tilesets.

Fix: Use speedy-blupi-1.tiled-project for SB1 levels (blp1xxx.blp) and speedy-blupi-2.tiled-project for SB2 levels (blp2xxx.blp).

Mistake 6: Not Making a Backup Before Editing

Symptom: You save corrupted data and cannot recover the original level.

Cause: Tiled overwrites the .blp file with no backup. If the save produces corrupted data (wrong size, bad object data), the original file is gone.

Fix: Before editing any level for the first time, make a copy of the entire level/ directory to a safe location. You can restore any level from the backup if something goes wrong.

Mistake 7: Setting Invalid Map Property Values

Symptom: The game crashes or shows a blank background/silence when loading the edited level.

Cause: Setting background, music, or ambiance to a value outside the valid range (which is not fully documented).

Fix: Only use values that appear in other official levels. Survey the existing 25–30 level files to find the range of values in use, and stay within that range.

Mistake 8: Placing a Player Start on a Non-Objects Layer

Symptom: The player start tile appears visually on the canvas but the player does not spawn at that position in-game.

Cause: The player-start tile was placed on the Foreground or Decoration tile layer instead of the Objects layer. On tile layers, objects from the player-start tileset are stored as tile IDs, not as BLP objects.

Fix: Player starts must be placed on the Objects layer as tile objects (Insert Tile Object tool). Delete the misplaced tiles from the tile layers and re-place them correctly.

Mistake 9: Forgetting to Save Before Testing

Symptom: Changes made in Tiled are not visible in the game.

Cause: The file was not saved after editing. Tiled keeps all changes in memory until you explicitly save.

Fix: Always press Ctrl+S before switching to the game. Check that the title bar tab no longer shows an asterisk (*) next to the file name.

Mistake 10: Editing a Level While the Game Has It Loaded

Symptom: The game shows the old version of the level, or file locking errors occur when trying to save.

Cause: Some operating systems lock files that are open by another process. If the game has loaded a level into memory and is running, the OS may prevent Tiled from writing to the same file.

Fix: Exit the game before saving from Tiled. On systems that do not lock files (most Linux distributions), this is less of an issue, but it is still best practice to exit the game before overwriting its data files.

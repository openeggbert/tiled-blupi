Tutorial 7: Set Player Start Position

Every playable level must have at least one player start position — the coordinate where Blupi (the player character) appears when the level begins. This tutorial explains the four player-start tile variants, how to place a start position, and how to verify it is valid.

Tileset used: Player starts use the player-start tileset, which has 4 tiles (indices 0–3). Each tile corresponds to a BLP type ID in the range 200–203. The class of all tiles in this tileset is Blupi.

The Four Player-Start Tile Variants

Tile IndexBLP Type IDDescriptionhflip
0200Standard start (facing right)No
1201Variant — purpose inferred from positionNo
2202Mirror of tile 0 (facing left)Yes
3203Mirror of tile 1Yes
Note: The exact in-game behavior difference between type 200, 201, 202, and 203 is inferred from the tile mirror flags in the TSX file, not from documented game behavior. The hflip flag on tiles 2 and 3 suggests they represent a mirrored/facing-left variant.

Step 1: Select the Objects Layer

  1. In the Layers panel, click Objects to make it active.

Step 2: Select the player-start Tileset

  1. In the Tilesets panel, click the player-start tab.
  2. You will see 4 small tiles. Tile 0 is the standard start.

Step 3: Place the Player Start

  1. Click tile 0 in the player-start tileset to select it.
  2. Activate the Insert Tile Object tool.
  3. Click on the canvas at the position where you want Blupi to start.
  4. The player start object appears at that grid cell.

Step 4: Verify the Position

The player start position should be placed:

  • On an empty cell (no foreground tile) or just above a solid ground tile — Blupi will fall if placed in midair unless there is a platform below.
  • Within the 100×100 grid boundary (coordinates 0–99 in both x and y).
  • Not overlapping another object.
Placement tip: In the original Speedy Blupi levels, the player start is typically placed one cell above a solid ground tile so that Blupi lands on it immediately when the level starts. If Blupi starts too high up, there may be a long fall at level start which can look unpolished.

Step 5: Move an Existing Player Start

  1. Press S for the Select Objects tool.
  2. Click the player start object on the canvas.
  3. Drag it to the new position, or use arrow keys to nudge.

Step 6: Check There Is Exactly One Player Start (Minimum)

A level must have at least one player start object with a type ID in range 200–203. If there is no player start, the game may crash or Blupi may not appear when the level loads.

To find the player start on a crowded map: use Edit → Find Objects (if available in your Tiled version) or toggle layer visibility to show only the Objects layer and scan for the Blupi tile.

How sblv.js Identifies Player Starts

When sblv.js reads a .blp file, it identifies player start objects by their BLP type field value: if type >= 200, the object is a player start and is placed using a tile from the player-start tileset. All other objects use the object-types tileset.

When writing, sblv.js checks the object's class. If the class is Blupi (set in the TSX file), the object is written as a player start type (type ID = 200 + tile_offset).

Done! You have placed a valid player start. Next: Tutorial 8: Create a Moving Object.

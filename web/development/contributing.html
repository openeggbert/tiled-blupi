Contributing

tiled-blupi is an open-source project hosted on GitHub (openeggbert/tiled-blupi). Contributions of all kinds are welcome — bug reports, documentation improvements, new object type support, reverse-engineering findings, and code fixes.

Types of Contributions

Contribution TypeHow to SubmitExamples
Bug reportOpen a GitHub IssueIncorrect tile rendering, wrong object type displayed, file size mismatch
Reverse-engineering findingGitHub Issue or Pull Request with documentationIdentifying what an unknown header field does, mapping a new object type ID
New object type supportPull Request modifying sblv.js and the TSX fileAdding support for type IDs that tiled-blupi does not yet know about
Documentation fixPull Request modifying README.md or (for this doc site) the HTML filesCorrecting wrong offset values, adding missing information
Tileset improvementPull Request modifying a TSX fileAdding missing tiles, fixing wrong image paths

How to Submit a Pull Request

  1. Fork the repository on GitHub.
  2. Clone your fork locally.
  3. Create a new branch for your change: git checkout -b add-type-44
  4. Make your changes following the guidelines below.
  5. Commit with a clear message: git commit -m "Add object type ID 44 to SB2 itemTypesArray"
  6. Push to your fork: git push origin add-type-44
  7. Open a Pull Request on GitHub.

Code Style Guidelines (sblv.js)

  • Use const for values that never change, let for variables that do.
  • Keep the constants at the top of the file.
  • When adding a new object type, add it to itemTypesArray at the end, not in the middle — inserting in the middle shifts all existing tile indices and breaks level files.
  • Do not add duplicate entries to itemTypesArray. Each BLP type ID should appear at most once.
  • Add a comment next to new array entries if you know their in-game purpose.

TSX File Guidelines

  • Always add new tiles at the end of the tileset (highest existing id + 1).
  • Update the tilecount attribute whenever you add or remove tiles.
  • Use paths relative to the TSX file location; do not use absolute paths.
  • Do not remove existing tiles — removing a tile changes all subsequent tile indices, breaking existing level files.

What to Include in a Bug Report

  • Tiled version
  • Operating system
  • Which game (SB1 or SB2)
  • The .blp file (attach to the Issue if possible, or the level number if it is an official level)
  • Steps to reproduce
  • Expected behavior
  • Actual behavior
  • Content of the Tiled Script Console (if relevant)

Accuracy Standards for Documentation

If you are contributing documentation (including this doc site), please follow the evidence tagging conventions:

  • ✓ sblv.js — fact confirmed by reading the extension source code
  • ✓ README — fact confirmed by the repository README
  • ✓ TSX — fact confirmed by reading a TSX file
  • ~ Inferred — reasonable deduction from available evidence, not directly stated
  • ? Needs verification — uncertain; should be marked with a callout box in the docs

Do not present inferred or uncertain information as confirmed fact.

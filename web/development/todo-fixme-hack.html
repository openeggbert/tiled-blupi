TODO / FIXME / HACK

This page documents known areas for improvement in tiled-blupi, based on the current state of the sblv.js extension code and the project structure. These are areas where the implementation is incomplete, incorrect, or uses a workaround.

Source: The items below are derived from reading the sblv.js source code and identifying known limitations. They supplement the Known Limitations page with a developer-focused perspective.

Header Fields: Unknown Region Is Zeroed

Classification: Known data loss / FIXME

Description: The BLP header (0x0000–0x0363) contains 868 bytes. Only a small number of fields are decoded by sblv.js. All remaining bytes in the header are written as zeros when the file is saved through tiled-blupi. This means any data the original game stored in undecoded header fields is lost on round-trip.

Impact: Potentially significant if the game reads any of the unmodeled header fields for per-level configuration. Unknown until the full header is reverse-engineered.

Fix needed: Complete reverse-engineering of the BLP header to identify all fields, then read them all as map properties and write them back correctly.

Object Struct Fields +0x02–+0x09 Are Zeroed

Classification: Known data loss / FIXME

Description: Eight bytes in the object struct (offsets +0x02 through +0x09) are not decoded by sblv.js. When writing, these bytes are written as zero. Any data the game stored here for each object is lost.

Fix needed: Identify what these fields contain through reverse-engineering; add them as Tiled object properties.

tileset_id and tile_id Not Reconstructed

Classification: HACK / Limitation

Description: The object struct stores tileset_id (+0x2A) and tile_id (+0x2C) fields. These are read from the BLP file and stored as Tiled object properties, but sblv.js does not use them when writing back — it derives the tileset and tile to use from the object's class and type, not from these stored values. This means tileset_id and tile_id values in the written file may differ from the original.

Impact: Unknown; if the game reads these fields at runtime, discrepancies could cause visual glitches.

Fix needed: Understand what the game does with tileset_id/tile_id and write them correctly.

No Object Count Warning

Classification: Missing feature / TODO

Description: When more than 200 objects are on the Objects layer, sblv.js silently writes only the first 200 and discards the rest. No warning or error is shown to the user.

Fix needed: Add a tiled.warn() call when the object count exceeds 200, so the user knows data was discarded.

// Suggested fix in write():
const objects = objectLayer.objects;
if (objects.length > MAX_OBJECTS) {
    tiled.warn("tiled-blupi: " + objects.length +
               " objects found, but BLP supports max " +
               MAX_OBJECTS + ". Extras were discarded.");
}

No Input Validation

Classification: Missing feature / TODO

Description: sblv.js does not validate that map properties (background, music, ambiance) or object properties (x, y coordinates) are within valid ranges before writing. An out-of-range value is written to the file without any warning.

Fix needed: Add range checks for known properties and warn (or clamp) when values are out of range.

Background Layer Not Written

Classification: By design (not a bug), but worth noting

Description: When reading, sblv.js adds a Background image layer to Tiled for visual context. When writing, this layer is not written back to the BLP file — only the background map property (an index) is written to the header. Any tiles the user might paint on the Background layer are silently ignored.

Fix needed: Add a user-visible note (via tiled.warn()) if the Background layer has been modified, informing the user their background edits will not be saved.

No Create-From-Scratch Support

Classification: Missing feature / TODO

Description: sblv.js's sblvMapFormat object does not implement the optional write() path for creating a new .blp file from scratch (without reading an existing one). Tiled only allows saving as "sblv" if a file was already opened in that format — you cannot create a new file using File → New Map and then save it as .blp.

Fix needed: Implement support for creating new .blp files. This would require the supportsFileType method to return true for new files (or rely on Tiled's "Save As" with format selection).

Trailing Bytes Purpose Unknown

Classification: Unknown / needs investigation

Description: The BLP file has 768 bytes after the object array (0xC224–0xC523). Their purpose is not known. sblv.js writes zeros here. If the game reads this region for any purpose, zeroing it may cause issues.

Fix needed: Reverse-engineer the game to determine if and how this trailing region is used.

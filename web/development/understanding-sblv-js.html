Understanding sblv.js

This page provides a developer-level walkthrough of the sblv.js extension source code. It explains the module's structure, key variables, and how the read and write functions are organized.

Module Structure

The file is a single JavaScript file (not an ES module — Tiled loads it as a plain script). It is organized into these logical sections:

  1. Constants — MAJOR_VERSION, DEFAULT_MINOR_VERSION, binary offsets (header fields, layer starts, object array start)
  2. itemTypesArray — The mapping from object-type tile index to BLP type ID
  3. Helper functions — Utility functions for reading/writing typed values from/to DataView
  4. read() function — Reads a .blp file and returns a Tiled Map object
  5. write() function — Writes a Tiled Map object to a .blp file
  6. sblvMapFormat object — The format descriptor object with name, extension, read, write, and supportsFileType properties
  7. Registration call — tiled.registerMapFormat("sblv", sblvMapFormat)

The read() Function

The read(filename) function:

  1. Opens the file using Tiled's BinaryFile API.
  2. Wraps the content in a DataView for typed access.
  3. Reads and validates major_version at offset 0x0000. If it does not match MAJOR_VERSION, returns null (Tiled will show an error).
  4. Reads header fields and stores them as map custom properties.
  5. Creates a TileMap with width=100, height=100.
  6. Creates and populates the Foreground tile layer using an edit batch (layer.edit() / edit.setTile() / edit.apply()).
  7. Creates and populates the Decoration tile layer similarly.
  8. Creates the Objects layer, then iterates over 200 object slots, creating Tiled tile objects for non-zero entries.
  9. Creates a Background image layer as a visual placeholder.
  10. Returns the completed TileMap.

The write() Function

The write(map, filename) function:

  1. Opens the file for binary writing using BinaryFile.
  2. Creates a DataView over a newly allocated ArrayBuffer of exactly 50,468 bytes (or the appropriate file size).
  3. Writes header fields from map custom properties.
  4. Zeros the unknown header region.
  5. Iterates all 100×100 cells of the Foreground layer and writes each tile value (or 0xFFFF for empty) to the column-major position in the buffer.
  6. Does the same for the Decoration layer.
  7. Iterates objects on the Objects layer: for each, writes the struct fields. Player starts (class=Blupi) are written with type 200+tile_index; regular objects use itemTypesArray. Remaining slots are zeroed.
  8. Writes trailing zeros.
  9. Commits the buffer to disk.

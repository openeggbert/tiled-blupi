Debugging the Tiled Extension

When sblv.js encounters an error, Tiled may show a vague error message or silently fail. This page describes the tools and techniques available to debug the extension.

The Tiled Script Console

Tiled provides a JavaScript console for viewing output from extensions:

  1. In Tiled, open View → Script Console (or find it in the Windows menu on some versions).
  2. The console shows all console.log(), console.warn(), and console.error() output from loaded extensions.
  3. If sblv.js throws an uncaught exception, it is displayed here with a stack trace.
Always check the Script Console first when a .blp file fails to open, saves incorrectly, or shows unexpected behavior.

Adding Temporary console.log Statements

To trace the execution of sblv.js, add console.log() calls to the extension source. Example:

// At the beginning of read():
console.log("sblv.js: reading file:", filename);

// After reading major_version:
console.log("major_version:", major_version);

// When encountering an object:
console.log("object at index:", i, "type:", type_id);

After adding these statements, restart Tiled (the extension is only loaded at startup). Then open a .blp file and watch the Script Console for output.

Remember to remove debug logging before committing. Excessive logging slows down the extension when opening large levels with many objects.

Verifying the Extension Is Loaded

To confirm sblv.js is loaded:

  1. Open the Script Console.
  2. Type: tiled.log(JSON.stringify(Object.keys(tiled))) and press Enter.
  3. Alternatively, check whether the file chooser shows "sblv" as an available format when using File → Open.

If the extension is not loaded, the Script Console will show an error like "Could not find extension file" or "SyntaxError in sblv.js".

Common Extension Errors and Their Causes

Error / SymptomLikely CauseFix
"Cannot read property 'read' of undefined"The BinaryFile API is not available — extension loaded before Tiled is fully initializedShould not happen in normal use; report as a Tiled bug if it does
"major_version mismatch"Opening an SB2 file with the SB1 extension, or vice versaUse the correct project file for the game version
Tiles show as pink/missing boxesPNG images not found at the relative path in the TSXVerify project is installed inside the game directory; check image/ folder exists
File saved but size is wrongAn error occurred during write; partial data was writtenCheck Script Console for exceptions; restore from backup
SyntaxError in Script Console on Tiled startA JavaScript syntax error in sblv.js (e.g., after manual editing)Fix the JS syntax error; use a linter (node --check sblv.js)
Objects missing after saveMore than 200 objects placed; extension silently dropped extrasCount objects and keep within the 200 limit

Using Node.js to Syntax-Check sblv.js

You do not need to open Tiled to check for syntax errors in the extension:

# Syntax check only (does not run the code):
node --check sblv.js

# If there is a syntax error, node prints it with line number.
# If there is no output, the syntax is valid.

Note: the script uses Tiled-specific APIs (BinaryFile, TileMap, etc.) that do not exist in Node.js. Running the script with node sblv.js will fail with ReferenceErrors. Use --check only.

Debugging a Specific Object's Properties

To check what values sblv.js reads for a specific object:

  1. Add a console.log inside the object-reading loop in read().
  2. Open the level in Tiled.
  3. Read the output to see every field of every object struct.

This is useful for identifying unknown fields or verifying that a specific type ID is being parsed correctly.
